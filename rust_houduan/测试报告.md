## 6. 代码审查发现

### 6.1 P1｜访问令牌永不过期

`接口/认证.rs:99` 签发时 `过期时间: None`，中间件又主动取消了对 `exp` 的要求：

```rust
let 令牌内容 = 令牌声明 { 主体: 用户编号, 过期时间: None, ... };   // 签发
校验规则.required_spec_claims.remove("exp");                      // 校验
```

并且有测试 **`访问令牌不包含过期时间且可通过校验`** 把这个行为固化下来。

**影响**：令牌一旦泄露（日志、前端存储、抓包）就长期有效，没有 `iat`/`jti`，无法主动吊销。目前唯一的兜底是每个请求都查一次 `用户."账号状态" = '正常'`，所以「禁用账号」能生效（这点做得对），但用户改密码、主动登出都对已签发令牌无效。

**建议**：加 `exp`（如 7 天）与 `iat`；如需即时吊销，加 `jti` + 黑名单表，或把 `密码修改时间` 也纳入校验。若「永不过期」是刻意的产品决策，至少应写进文档并在前端做无感刷新。

### 6.2 P1｜地图接口完全无鉴权

```rust
pub(crate) async fn 逆向地理编码(State(状态): State<应用状态>, 查询: Query<...>) -> ...
pub(crate) async fn 周边地址(State(状态): State<应用状态>, 查询: Query<...>) -> ...
```

两个 handler 都没有取 `当前用户`，`/_AMapService/{*path}` 代理同样没有。任何人扫到域名就能匿名调用，每次消耗你的高德 Web 服务配额（按次计费），并可借 `jscode` 代理绕过你自己的前端限制。

**建议**：至少要求登录后再转发；或按 IP + 用户做配额（如每用户每分钟 30 次）。代理路径建议同样加身份校验。

### 6.3 P1｜无限流、无爆破防护

全项目未引入 `tower_governor` 或任何限流中间件（`grep governor|rate_limit|TimeoutLayer` 无结果）。`/api/v1/auth/login` 与 `/register` 可被无限次尝试。

Argon2 默认参数（m=19456, t=2, p=1）让单次校验约几十毫秒，形成天然节流，但并发请求会直接把 CPU 打满——攻击者用 100 并发就能让正常登录排队。

**建议**：登录接口加「IP + 登录名」双维度限流与失败次数锁定；全局限流中间件兜底。

### 6.4 P2｜委托详情匿名可读

`GET /api/v1/tasks/{id}` 不要求登录（随机 UUID 返回 `404 委托不存在` 而非 `401`），返回完整 `任务视图`：标题、描述、发布者 UUID、接单者 UUID、**精确经纬度**、报酬、截止时间。

`GET /api/v1/tasks`（委托广场，仅 `投标中`）同样是匿名可读——这个按产品逻辑讲得通，但广场与详情应保持一致口径。若详情里将来出现联系方式，就是明确的隐私泄露。

**建议**：详情接口按「状态 + 关系」做可见性控制：`投标中` 或本人参与才可读；否则 404。广场列表建议隐藏精确坐标，只给到城市级。

### 6.5 P2｜框架英文错误消息透传

统一响应约定是中文消息，但 axum 的 extractor rejection 会把英文原文塞进 `消息`：

```
{"状态码":422,"消息":"Failed to deserialize the JSON body into the target type: missing field `login_name` at line 1 column 2"}
{"状态码":400,"消息":"Invalid URL: Cannot parse `id` with value `not-a-uuid`: UUID parsing failed: invalid character: found `n` at 0"}
```

对外暴露了 serde 字段名与解析器内部细节，也与「所有接口响应用中文业务字段」的自有测试精神不一致。

**建议**：自定义 `Path`/`Query`/`Json` 的 rejection 映射，统一转成 `应用错误::请求错误("请求参数格式无效")` 一类中文消息，细节留给日志。

### 6.6 P2｜列表接口缺少分页上限

| 接口 | 情况 |
|------|------|
| `GET /api/v1/my/claimed-tasks` | 无 `LIMIT` |
| `GET /api/v1/my/published-tasks` | 有分页 ✅ |
| `GET /api/v1/tasks/{id}/bids` | 无 `LIMIT` |
| `GET /api/v1/my/groups` | 无 `LIMIT` |
| 群成员列表 | 无 `LIMIT` |

对比之下 `查询任务列表`、群消息、好友列表都做了 `clamp(1, 100)`，说明团队知道该限制，只是漏了几处。历史数据积累后，单个重用户可能一次拉回几千行。

### 6.7 P3｜其他

| 项 | 说明 |
|----|------|
| `rand` 未使用 | 建议删除依赖 |
| 3 处 `collapsible_if` | `接口/任务.rs:734`、`963`、`964`，`cargo clippy --fix` 可自动修 |
| 投标索引排序不匹配 | 索引是 `("投标截止时间") WHERE 任务状态='投标中'`，而广场查询按 `创建时间 DESC` 排序，用不上索引排序；建议改 `("创建时间" DESC)` 或建复合索引 |
| apalis 作业表只增不删 | `工作者.rs:315` 每 2 秒 push 一个扫描任务，apalis 的 jobs 表无清理策略，长期运行会持续膨胀，建议定期 `DELETE` 或按保留期清理 |
| 过期处理的语句顺序 | `工作者.rs:117` 先 `退款委托报酬`，再 `UPDATE 任务`，若 `rows_affected()==0` 会 `continue` 但事务末尾仍提交 → 理论上「钱退了、状态没改、事件没发」。当前靠 `SELECT ... FOR UPDATE OF t` 行锁使该分支不可达，但顺序反了，未来改动容易踩坑。建议先更新状态、判 `rows_affected`，再退款 |
| 每请求查库取角色 | `验证可选身份` 对每个带令牌的请求都做 2 次 JOIN + `array_agg`，高频下是额外往返；可考虑把角色写入令牌（但会牺牲即时性） |

## 7. 值得肯定的设计

这些点在同规模项目里不常见，建议保持：

1. **积分台账严谨**：`转移积分` 把余额校验写进 `UPDATE ... WHERE "可用积分" >= $2`，由数据库保证不超扣；账户行 `FOR UPDATE` 按账户号排序加锁，避免死锁；`总积分` 用 `checked_add`。
2. **幂等真正落地**：管理员发放积分用 `pg_advisory_xact_lock` + 重放查询 + 「同一幂等键用于不同参数」检测，不是简单加个唯一索引。
3. **可靠消息用事务发件箱**：业务事务内写 `事务发件箱`，worker 用 `UPDATE ... WHERE 投递状态='待投递' AND 下次尝试时间 <= now()` 抢占式领取，配合 MQTT QoS1 的 `PubAck` 确认才标记已投递 —— 这套组合能防丢消息。
4. **状态机独立成纯函数**：`计算任务状态` 无 IO，3 项测试覆盖了越权与非法流转，改动时能快速验证。
5. **接口契约测试化**：`所有接口响应均使用中文业务字段名` 把「字段不能改回英文」变成可执行断言。
6. **数据库索引到位**：`任务` 的部分索引、`积分交易(操作者, 幂等键)` 唯一索引、`经纬` 的 GIST 空间索引、`群_成员` 的有效成员唯一索引，说明索引是照着查询设计过的。
7. **路径穿越防护有效**：白名单 + 字符集校验 + `..` 拒绝，实测 `--path-as-is` 与 `%2e%2e` 都被拦在本地，未触达上游。

## 8. 未覆盖的部分

| 未测项 | 原因 |
|--------|------|
| 写接口全链路（注册→登录→发布→投标→接单→积分） | 按约定只做只读 E2E，避免向真实库写入账号和业务数据 |
| MQTT 实际投递 | 未向生产 broker 发布消息 |
| 高德真实调用 | 会消耗配额，只测了本地拒绝路径 |
| 并发与压测 | 本机无压测工具，`curl` 循环测的是进程开销 |
| 多实例 / 故障恢复 | 需要独立环境编排 |
| Linux 部署包（`build-linux-musl.sh`） | 本机为 Windows，未执行 |

如需补齐写链路测试，建议单独准备一个一次性数据库（或用 `CREATE DATABASE ... TEMPLATE`），跑完整业务流后整库丢弃。

## 9. 建议处理顺序

1. **给访问令牌加过期时间**（6.1）—— 改动最小，收益最大
2. **地图接口加鉴权或配额**（6.2）—— 直接关系到费用
3. **登录限流与失败锁定**（6.3）
4. **委托详情做可见性控制**（6.4）
5. **rejection 统一映射为中文**（6.5）
6. 给漏掉的列表接口补 `clamp`（6.6）
7. 清理 `rand`、跑 `clippy --fix`、调过期处理语句顺序（6.7）
