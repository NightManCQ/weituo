## 2. 问题清单

### E1（阻断）字符串内联格式捕获失配 → 2 个 E0425

汉化把**变量名**改成了英文，但 `format!` 字符串里的 `{变量}` 在保护区内没跟着改，于是名字对不上。

```
error[E0425]: cannot find value `状态` in this scope
   --> src\接口\任务.rs:681:41
681 |   应用错误::冲突(format!("当前状态“{状态}”不允许此操作"))
    |                                  ^^^^ not found in this scope

error[E0425]: cannot find value `路径` in this scope
   --> src\接口.rs:338:64
338 |   let mut 上游地址 = reqwest::Url::parse(&format!("https://{主机}/{路径}"))
    |                                                        ^^^^ not found in this scope
```

原始代码（`src/接口/任务.rs:681`、`src/接口.rs:338`）本来是完全合法的 Rust 2021 内联捕获：

```rust
任务状态错误::状态不允许(状态) => 应用错误::冲突(format!("当前状态“{状态}”不允许此操作"))
let mut 上游地址 = reqwest::Url::parse(&format!("https://{主机}/{路径}"))
```

链条是这样的：

1. `秀编 来`：字符串被保护，`"{状态}"` 原样写入 `源码/接口/任务.秀`；
2. `秀构`：`状态`（函数参数/匹配绑定）命中词表 `状态 → status`，被改名；字符串里的 `{状态}` 不动；
3. rustc：找不到 `状态`。

`{主机}` 之所以没炸，纯粹因为「主机」不在词表里——**同一个文件里两行，一行炸一行不炸，取决于词表有没有收录**。

**最小补丁**（改 `源码`，改完行数不变）：

```diff
- 应用错误::冲突(格式化!("当前状态“{状态}”不允许此操作"))
+ 应用错误::冲突(格式化!("当前状态“{}”不允许此操作", 状态))

- 让 可变 上游地址 = reqwest::Url::解析(&格式化!("https://{主机}/{路径}"))
+ 让 可变 上游地址 = reqwest::Url::解析(&格式化!("https://{}/{}", 主机, 路径))
```

### E2（阻断）响应字段被英化 → JSON 契约断裂

第 2 轮补完 E1 后编译通过，但项目自带的契约测试挂掉：

```
---- 共享::响应字段测试::所有接口响应均使用中文业务字段名 ----
assertion `left == right` failed
  left: ["position", "任务状态", ...]        ← 转译后实际返回
 right: ["任务状态", "任务编号", "位置", ...]  ← 契约要求
```

原因：`任务视图` 的字段 `位置: Option<任务位置>` 被汉化成 `position`，而 serde 默认按字段名序列化，于是**接口对外 JSON 的键从 `"位置"` 变成了 `"position"`**。

这比编译错误更危险：如果没有那条契约测试，它会安静地上线，然后前端拿不到 `位置` 字段。

**最小补丁**（`源码/共享.秀` 第 178 行）：

```diff
+ #[serde(rename = "位置")]
  公有(箱) 位置: 选项<任务位置>,
```

### E3（设计缺陷）14 个中文标识符被当成词表译名，481 处被英化

词表（655 条「中文 → 英文」）里有一批词，正好和本项目的**用户自定义标识符**同名，汉化时被一起翻掉：

| 中文标识符 | 被改成 | 出现次数 |
|---|---|---|
| `状态` | `status` | 157 |
| `请求` | `Request` | 110 |
| `位置` | `position` | 50 |
| `参数` | `args` | 48 |
| `错误` | `error` | 34 |
| `任务` | `task` | 32 |
| `路径` | `path` | 17 |
| `结果` | `Result` | 14 |
| `时间` | `time` | 6 |
| `字符` / `接受` / `权限` / `读取` / `来源` | `char` / `accept` / `Permissions` / `read` / `source` | 各 2–3 |

影响面：13/15 个文件、481 处标识符改名。后果分三类：

- **编译失败**：名字被引用的地方在保护区里（E1）；
- **契约变化**：名字参与序列化（E2）；
- **风格破坏**：变量/参数/函数名变成英文，`请求` 甚至变成 `Request` 这种大写开头的局部变量名——例如 `接口/管理.rs`：

```rust
// 转译前
async fn 设置用户状态(应用状态: 应用状态, 请求: axum::http::Request<...>, ...)
// 转译后
async fn 设置用户状态(应用状态: 应用状态, Request: axum::http::Request<...>, ...)
```

原本全中文命名的代码，往返一趟就变成「中文函数名 + 英文变量名」的混合体。

## 3. 根因

三层原因叠加，本质是**词表分不清"关键字"和"用户标识符"**：

1. **词表是一张扁平的双向映射**：655 条「中文→英文」里，既有 `让→let`、`向量→Vec` 这种语法/标准库词，也有 `状态→state`、`路径→path` 这种**普通英文单词**。后者天然会和用户自己起的中文名撞车，撞了必翻。
2. **两个方向不对称**：`秀化`（Rust→秀）只翻英文，中文标识符原样保留，看着没问题；`汉化`（秀→Rust）遇到中文就翻，把用户自己的命名一起带走。
3. **保护区与改名区不联动**：字符串、`#[...]` 属性被保护是对的，但保护区里引用的标识符（`{状态}`、serde 字段名）不会跟着改名，于是同一符号在两个区里成了两个名字。

## 4. 修复建议（按性价比排序）

| 优先级 | 建议 | 说明 |
|---|---|---|
| **P0** | 汉化时建立「本文件已声明的标识符」白名单，命中白名单的中文词不翻译 | 只需在替换前扫一遍 `让 X` / `方法 X` / `结构 X` / 字段声明 / 参数列表，收集定义名。改动局限在 `智能替换.rs`，不动词表。这一条能同时根治 E1、E2、E3 |
| **P0** | 词表分级：`关键字` / `标准库` / `常用词` 三类，只有前两类参与汉化 | 「状态/路径/位置/参数」这类普通名词应归入第三类，只用于 秀化 提示，不用于 汉化 替换 |
| P1 | `format!` 内联捕获单独处理：字符串里 `{名字}` 也要查白名单，同步改名 | 作为白名单方案的兜底，防止 `{状态}` 与变量名脱钩 |
| P1 | 行尾策略统一：读什么写什么，或统一 LF | 现在同一批输入产出不一致（E4） |
| P2 | 给 `秀构` / `秀编` 加 `--保持标识符` 开关 | 用于「只想中文化关键字、不想动命名」的场景，本项目的诉求正是这个 |
| P2 | `秀构` 覆盖 `src/` 前先备份或要求确认 | `编译.rs:113` 直接 `remove_dir_all(src)`，一旦转译有损就是不可逆覆盖 |
